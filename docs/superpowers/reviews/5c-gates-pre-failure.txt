=== gate 24 "datatruth" leg f — table sort determinism — 2026-08-04 ===

PM-review §P1-7. `/company/lockheed-martin/` rendered its Lobbying Activity
filing years as 2024, 2026, 2025. Root cause: the exporter's fct_influence
query had no ORDER BY at all, so the table showed whatever order DuckDB
returned — 33 of the 66 families with filings were out of order. The audit
found the same class of defect in five more payloads: program mentions (240 of
244 lists not newest-first), company mentions, program/company awards, the

lists. Two more (jbook details, jbook narratives) had ordered LEADING keys but
left ties to the query plan, which silently decided the Budget Details project
grouping and the {pe}/line{n} gate-23 entity ordinals.

CONTRACT the leg enforces on the BUILT artifact:
  [data-sort-table="<name>"] [data-sort-order="<key>:asc|desc"]   container
  [data-sort-value="<v>"]                                          each row
data-sort-value is the COMPARATOR'S OWN INPUT serialized (including the
±Infinity sentinels the tables use for missing values), not a rendered cell —
so what is checked is the order the sort actually produced, and a page cannot
satisfy the leg by rendering a pretty cell over a wrong row order. Client
tables emit their LIVE sort state, so the declaration stays true after a
reader clicks a header.

Two halves, because either alone is toothless:
  (1) five enumerated (page, table, order, min-rows) contracts that MUST be
      present with the exact declared order — a table cannot pass by dropping
      its attribute or quietly flipping to asc, and a table rendering fewer
      than min-rows fails rather than passing vacuously;
  (2) a sweep of 386 built pages (200 company + 106 district + 80 program):
      EVERY [data-sort-table] found must be monotonic, and fewer than 100
      declared tables across the sweep is itself a failure.
