# Fiscal Receipts — Product & Engineering Review

**Reviewer:** Product review, acting as skeptical journalist / Hill staffer / citizen
**Date:** July 30, 2026
**Build tested:** live site, footer stamp "Data as of July 28, 2026"
**Method:** Chrome at 1440×900 and 400×850. Clicked receipts on real figures and read the underlying PDFs and workbooks; ran the three core user journeys; probed search, coverage seams, 404s, permalinks, share metadata, page weight, and contrast. Every finding below has a reproduction path.

---

## Verdict

The hard part is done and it is done well. The methodology page is the most honest primary-source disclosure I have read on a public data site. The PDF receipt — rendered page, highlighted cell, Enlarge, SHA-256, retrieval date — genuinely delivers the promise. The Flow page's framing ("two rivers, deliberately kept apart… 98.7% of the FY2026 request is not yet crosswalked: an honest gap, not an absence of contractors") is the sentence that should be on the homepage. The Data Explorer, the anomaly feed with published thresholds, the per-program OG cards, and the empty-state copy on Awards and Lobbying are all better than they need to be.

The problem is not the receipts. The problem is the **summary layer sitting on top of them.**

On the F-35 page — the site's flagship program, the one linked from the homepage hero — the same fiscal year is reported with different values in different places, each correctly cited, with nothing telling the reader why they differ. FY2024 appears as both $5.25B and $5.57B. FY2025 appears as "—", $4.97B, and $4.49B. FY2026 appears as $4.09B and $3.56B. The homepage headline and the social share card both propagate one of the conflicting values.

This is the one class of defect that can end the product. A reporter who cites $5.25B from the summary card and then gets shown $5.57B from the table two inches below has been burned by the site, and the receipts make it worse rather than better: they prove the site knew both numbers. Everything in P0 below is a variation on this theme, and the systemic fix (§P0-1, plus the CI invariant in §Systemic Fix) is the single highest-leverage engineering change available.

Second-order: the site's three headline capabilities — follow-the-dollar flows, research dossiers, district lens — are implemented at roughly 1%, 3%, and 24% coverage respectively. The disclosure of this is exemplary. The roadmap for closing it is invisible to a visitor, which makes the site feel like a demo rather than a resource. That is a positioning and sequencing problem, addressed in §Coverage.

# P0 — Trust-breaking

## P0-1. The same fiscal year, same program, same label resolves to different values on one page

**Where:** `/program/ATA000/` (F-35). Spot-checked and reproducible; treat as systemic across program pages, not as one bad row.

**Repro:** Load the page. Read these five places top to bottom.

| Location | Label | Value | Fact ID |
|---|---|---|---|
| Budget Figures card | FY24 Actuals | **$5.25B** | `#8b2746cb` |
| Budget Trajectory | FY24 | **$5.57B** | `#2365279a` |
| Decade table, Actuals row | FY24 | **$5.57B** | |
| Exhibit P-1 line items | FY24 Actuals | **$5.57B** | |
| Budget Details (R-2/P-40) | FY24 Actuals | **$5.25B** | `#8b2746cb` |

**Root cause, confirmed by reading the receipts.** Both figures are correct and both cite properly. They are different rows of the same government table:

- `$5.25B` → PDF citation resolves to *FY26 Air Force Aircraft Procurement Vol I.pdf*, p.55, Exhibit P-40 Resource Summary, row **"Net Procurement (P-1) ($ in Millions)"**, FY2024 column = **5,247.070**
- `$5.57B` → workbook citation resolves to *p1_display.xlsx*, sheet Exhibit P-1, cells O839:O841 = **5,565,655 USD thousands**, which is the **"Total Obligation Authority"** row on that same PDF page

The bridge between them is printed one row above, on the very PDF page the site renders: **Plus CY Advance Procurement 318.585**. 5,247.070 + 318.585 = 5,565.655. The site has the reconciliation in hand and does not show it.

**Same page, same class of defect, FY2025 and FY2026:**

| Label | Card | Decade table | Budget Details |
|---|---|---|---|
| FY25 | **—** | $4.97B enacted / $4.96B request | **$4.49B** |
| FY26 | **$4.09B** request | $4.09B request | **$3.56B** request / $3.56B base |

**Why it matters.** A reader has no way to know that "FY24 Actuals" means two different accounting concepts in two cards eight hundred pixels apart. The receipts do not rescue this, because both receipts are valid — the ambiguity is in the label, not the source. For a product whose entire brand is defensibility, an unlabeled definitional collision is worse than a missing number.

**Fix.**
1. Every rendered figure carries an explicit **basis**: exhibit + row name + edition. Render it inline, small, always visible — `FY24 actuals · P-40 Net Procurement (P-1) · PB2026` — not only inside the drawer.
2. Where two bases for the same (program, year) exist, render **one** as primary and show the other in a reconciliation strip: `$5.25B Net Procurement + $0.32B CY advance procurement = $5.57B total obligation authority`. You already parse both; this is a presentation join, not new ingestion.
3. Pick one basis as canonical for KPI cards, homepage, OG cards, and the anomaly feed, and use it everywhere. Total Obligation Authority is the defensible default — it is what Congress provides.
4. Add the CI gate described in §Systemic Fix so this cannot regress.

## P0-2. Summary cards report "no data" while the same page displays the data

**Where:** `/program/ATA000/`

**Repro:** The top-of-page summary reads **"WHAT CHANGED — No FY25→26 comparison — trajectory data incomplete for this line."** The FY25 Total card reads **"—"** and FY25→26 Change reads **"—"**. Scroll 600px. The decade table shows FY25 Enacted **$4.97B**, FY25 Request **$4.96B**, FY26 Request **$4.09B**. The Budget Details table shows FY25 Total **$4.49B**.

**Why it matters.** This is the inverse of over-claiming, and for this audience it is just as damaging. The site's discipline is "cited or absent" — but here something *present and cited* is being reported as absent, in the highest-attention slot on the page, on the largest program in the corpus. A staffer skims the three summary cards, concludes the site has no FY25 figure for the F-35, and leaves. The site had three of them.

Same page, same pattern: **"WHO GETS IT — No award linkage at high confidence."** True with respect to the crosswalk, and honestly worded, but the first question every visitor brings to the F-35 page is who builds it, and the answer renders as a blank.

**Fix.**
1. Compute the summary cards from the **same resolved fact set** the detail sections use, not from a narrower upstream table. This is almost certainly a query-scope bug rather than a data gap — the fix is to point the summary at the union, with the basis label from P0-1.
2. When a value truly is unavailable, distinguish the reasons: *not published in this edition* / *program absent from this edition* / *we have not ingested it yet* / *classified*. "—" currently collapses four different meanings.
3. For "WHO GETS IT" on a program with no crosswalk link, say what you *do* know instead of nothing: named primes appear verbatim in the J-book justification text you already render.

## P0-3. The copy-as-footnote output omits units and fiscal year

**Where:** citation drawer, PDF tier. `/program/ATA000/` → click `$5.25B` → Copy as footnote.

**Actual output:**

```
F-35: 5,247.070 — FY26 Air Force Aircraft Procurement Vol I.pdf, p.55;
sha256:528d14414585406684021e04e74632cccf4b40f8ba039f89f8af1ddebc7bc01e;
retrieved 2026-07-05; https://fiscalreceipts.com/program/ATA000/
```

Compare the workbook tier, which does carry a unit:

```
F-35: 5,565,655 USD thousands — p1_display.xlsx, sheet Exhibit P-1,
cells O839,O840,O841; sha256:...; retrieved 2026-06-10; https://...
```

**What is missing from the PDF-tier footnote:** the unit (`$ in Millions`), the **fiscal year**, and the row name. A bare `5,247.070` pasted into a draft is not just incomplete, it is hazardous — nothing in it distinguishes millions from thousands, and a factor-of-1000 unit error in a defense-spending story is a correction.

**Why it matters.** This button is the product's contract with its primary user. It is the artifact that leaves the site and appears in someone's published work. It is the last place to be inconsistent between tiers.

**Fix.** One footnote formatter, both tiers, with a fixed field set: program, **fiscal year**, row/field name, value **with unit**, document title (not filename), page or sheet+cells, SHA-256, retrieval date, **fact permalink** (see P0-4). Offer Chicago / AP / BibTeX / JSON variants — three lines of formatting for a large credibility gain with the newsroom audience. Suggested target:

> Fiscal Receipts, "F-35 (ATA000), FY2024 Net Procurement (P-1): $5,247.070 million." Office of the Under Secretary of Defense (Comptroller), *FY2026 Air Force Aircraft Procurement, Vol. I*, Exhibit P-40, p. 55. SHA-256 528d1441…; retrieved 2026-07-05. https://fiscalreceipts.com/fact/bb54b165

## P0-4. Fact IDs are displayed everywhere and are not addressable

**Where:** every figure, once Receipts mode is on. Drawer footer shows `fact #bb54b165`.

**Repro:** `/fact/bb54b165/` → **404**. `/facts/bb54b165/` → 404. `/f/bb54b165/` → 404. `/program/ATA000/#fact-bb54b165` → loads at scroll position 0, no drawer, no highlight.

**Why it matters.** The methodology page states: *"Permalinks continue to resolve permanently."* Today no permalink to a fact exists. The consequences are concrete: an editor cannot be sent to the exact receipt behind a contested number; a reporter cannot bookmark the cell; the footnote can only point at a page that may contain a dozen figures. Receipts mode currently hands the user an identifier with nothing to do with it.

**Compounding defect — the two IDs for one figure disagree.** With Receipts mode on, the chip beside the FY24 Actuals card reads **`#8b2746cb`**. Click that same figure and the drawer footer reads **`fact #bb54b165`**. Same number, same click target, two different identifiers, neither labeled. Whatever the internal distinction (measure vs. citation, presumably), from the outside it means neither ID can be treated as *the* identifier for the number — which is the one thing Receipts mode exists to provide. Verified independently for the FY26 request, where chip and drawer agree (`#0a323362`), so this is an inconsistency rather than a uniform scheme.

**Fix.**
1. `GET /fact/{id}` → canonical page for that fact: value, basis, rendered source excerpt, hash, retrieval date, and a link to the parent entity. Server-rendered, indexable, permanent.
2. `#fact-{id}` on any page scrolls to the figure, focuses it, and opens the drawer.
3. Put the fact permalink in the footnote (P0-3) and behind a click on the Receipts-mode chip.
4. Resolve to **one** public identifier per rendered figure. If two ID namespaces must coexist, label them (`measure` vs. `citation`) and make both resolvable.
5. Honor the supersede-not-delete policy here: a superseded fact resolves to a page showing the correction and linking the original.

## P0-5. Unqualified superlative on the homepage, computed on the narrower basis

**Where:** `/` hero — "LARGEST FY2024 ACTUAL IN THE J-BOOKS — **$5.25B** — F-35 ATA000 F"

Two problems compounding. First, `$5.25B` is the Net Procurement basis from P0-1; on the Total Obligation Authority basis the same program is $5.57B, so the site's single most prominent number is the one it contradicts elsewhere. Second, "largest FY2024 actual in the J-books" is scope-unqualified. The corpus is 1,741 R&D and procurement program elements. It excludes military personnel, O&M, and most shipbuilding. A first-time reader reasonably concludes that the largest single thing in the FY2024 Pentagon budget was $5.25B, which is wrong by more than an order of magnitude — and being wrong about scale on the homepage of a transparency site is the exact failure mode the site exists to correct.

**Fix.** Restate as "Largest single R&D or procurement program element in our corpus (1,741 lines; excludes personnel, O&M, and appropriations not covered by the R-1/P-1 rollups)" and switch to the canonical basis. Apply the same scope qualifier to the "Largest FY25→26 changes" module and to the anomaly feed's superlatives.

# P1 — Erodes trust or blocks a core job

## P1-1. The citation affordance is nearly invisible, and it is off by default

Two independent problems on the product's defining interaction.

**Contrast.** Measured computed styles on `/program/ATA000/`:

| Element | Value | Required |
|---|---|---|
| Citation underline (`border-bottom`) vs. background | **1.26:1** | 3:1 (WCAG 2.1 AA, 1.4.11 non-text contrast) |
| "source" chip underline | **1.23:1** | 3:1 |
| "source" chip font size | **10px** | ≥12px, ideally 14px |
| Legend text ("blank = series not published…") | **10px** | ≥12px |

16 elements on the page render below 13px; the minimum is 10px. The dotted underline that means *this number has a receipt* is at 1.26:1 — effectively gone on a dim laptop, in sunlight, or for anyone with mild low vision. The affordance carrying the entire value proposition fails the applicable contrast requirement by more than 2×.

**Default state.** The header control is labeled only **"Receipts"**, and its accessible name is *"Receipts mode: off. Click to enable citation chips."* A first-time visitor sees no fact chips until they find and toggle an unexplained button. The site is named Fiscal Receipts; its receipts are opt-in.

**Fix.** Raise the underline to ≥3:1 and give it a hover/focus state that reads as interactive. Raise provenance chips to 12–14px. Default Receipts mode **on** for first-time visitors, with the toggle relabeled "Show fact IDs" and persisted per user — or better, retire the mode and make chips a hover-reveal so the page is calm at rest but the affordance is always one hover away.

## P1-2. The "WHAT IT IS" card is a template stub, and a good sentence already exists 3,000px below

**Repro:** `/program/ATA000/` top card reads *"F-35 – a procurement program run by Air Force."* Scroll to Program dossier → What it is: *"F-35 (budget line ATA000) is a U.S. Air Force procurement line funded in the Aircraft Procurement, Air Force account. The line procures the F-35 Joint Strike Fighter, a family of aircraft with three variants — the F-35A conventional takeoff and landing, the F-35B short takeoff and vertical landing, and the F-35C carrier variant — sharing maximum commonality to minimize life-cycle cost."* Every sentence carries a fact ID.

The dossier prose is good. The summary card is auto-generated filler that reads, on the largest program in the corpus, like the site has nothing to say. **Fix:** hoist the dossier's first one or two sentences into the card for the 50 programs that have dossiers; for the rest, generate from J-book fields (account, appropriation, exhibit, quantity) rather than a name-plus-org template. This is a very cheap change with an outsized effect on perceived depth.

## P1-3. Entity resolution splits one corporate family, and the confidence chip is uninformative

**Repro:** `/companies/`

| # | Company | Obligations | Confidence |
|---|---|---|---|
| 4 | RAYTHEON COMPANY | $43.7B | medium |
| 6 | RTX CORP | $24.6B | medium |

Raytheon renamed to RTX in 2023. These are one family listed as two, understating the combined position by roughly half and misordering the top ten. It is the most widely known defense rename of the decade, sitting at #4 and #6.

Separately, **all 200 rows read "medium"** — name-inference. The methodology defines "high" as a SAM.gov registered common parent, and that tier appears unused at the top of the list. A confidence chip that never varies conveys nothing while adding 200 amber badges of visual alarm.

**Fix.** Hand-curate a rename/acquisition table for the top ~50 families (Raytheon→RTX, L3→L3Harris, Rockwell Collins→Collins→RTX, Orbital ATK→Northrop, Sikorsky→Lockheed) with effective dates, and expose it as its own cited page — that table is itself a publishable asset. Promote the top 20 to high confidence via SAM.gov resolution. Suppress the chip when it is uniform across a table and state the method once in the header.

## P1-4. Search: punctuation, ranking, and result titles

`/` → Cmd-K. Search is genuinely strong — full-text across documents with highlighted snippets, and it finds Ground Based Strategic Deterrent from the query "Sentinel" via document text, which is impressive. Three defects:

**"F35" does not find F-35.** The PROGRAMS section returns **RC-135** and **C-135**; F-35 appears only under IN DOCUMENTS. Users type F35, B21, KC46, F15EX constantly. Normalize by stripping non-alphanumerics on both sides of the match.

**Name-match outranks significance.** "Sentinel" ranks *Sentinel Mods* (a minor line) above *Ground Based Strategic Deterrent* ($4.15B FY26), which is the program actually named Sentinel. Blend FY26 magnitude and document-hit-count into ranking, and ship an alias table with visible "also known as" chips: Sentinel↔GBSD, Raider↔B-21, JSF↔F-35, Sentinel↔LGM-35A.

**Lobbying results show raw URL paths as titles.** Searching "Lockheed" returns four results titled `/filing/813b1886-65d2-4abb-9d6f-c4a8ce7dd56c/`, indistinguishable from one another. They should read "Lockheed Martin — Penn Avenue Partners, 2024 Q3". The same snippet shows a field-concatenation bug: `"126 unique entity identifiersTotal obligations: $135.4Bme…"` — missing separator.

## P1-5. Corpus size is stated four different ways

| Location | Count |
|---|---|
| `/programs/` | 1,741 program elements |
| `/years/` | "all 1993 program pages are browsable" |
| `/methodology/` | "1,741 of 1,993 program pages with full detail" |
| `/data/` → `dim_programs` | **326 rows** |
| `/data/` → `fct_budget_trajectory` | 1,982 rows |

A user who cites "1,741 programs" and then opens the Data Explorer to verify finds 326. Whatever the modeling reason, from outside it reads as an inconsistency in the site's account of itself, on the one page built to let people check the site's work. **Fix:** one canonical corpus-definition block, reused everywhere, stating total program pages, how many have detail-grade data, and what each dataset row-count represents. Rename or document `dim_programs` so its scope is self-evident.

## P1-6. Currency formatter breaks above $1T, and district KPIs lack a year range

**Repro:** `/district/` → `**$3657.4B**` labeled "all-district obligations (geography total)".

Two problems. The formatter does not roll over to trillions — should read `$3.66T`. And $3.657 trillion sits in a card next to "8.0B linkable dollars" with no year range on either, inviting the reading that the Pentagon spent $3.66 trillion in a year. Also on `/district/CO-05/`: two adjacent cards both show **$1.14B**, labeled "linkable obligations" and "cited (USAspending)" — the same number twice under two labels reads as a bug even when it isn't.

**Fix.** Extend the formatter through T. Put an explicit range on every aggregate (`FY2017–FY2026`). Merge the duplicate district cards. Also note the range is stated inconsistently across the site — `/companies/` says FY2017–FY2025, the Lockheed page says "across the full USAspending dataset," `/district/` says nothing.

## P1-7. Lobbying table rows are unsorted

`/company/lockheed-martin/` → Lobbying Activity rows appear in the order **2024, 2026, 2025**. Sort descending by filing year. Audit every table for a deterministic default sort; on a site about verifiability, an obviously unsorted table reads as carelessness and invites doubt about the numbers in it.

## P1-8. The anomaly feed reports percentages without magnitudes, and has no feed

`/feed/` items read "Minuteman Squadrons increased 79% FY25→26" with `+79%` as the only figure. A +79% swing on a $50M line and on a $5B line are different stories; percent-only hides which one this is. Show both: `$X → $Y (+79%)`.

And a page called Feed has no subscription. `/rss.xml` → 404, `/feed.xml` → 404. Journalists and staffers on this beat live in RSS and email alerts, and "the site that tells you when a program's budget moves, with the receipt attached" is a genuinely differentiated distribution hook. **Fix:** RSS/Atom for the whole feed and per event type, plus per-program and per-company watch feeds. Highest-ROI growth feature on the list.

## P1-9. Workbook-tier citations do not show the cell, and the unit label contradicts the value

`/program/ATA000/` → click `$5.57B` in the P-1 table:

- Header reads **"$5.57B  USD thousands"** — the displayed value is in billions and the unit label says thousands. The raw `5,565,655` is nowhere on screen; it exists only inside the copied footnote. The PDF tier gets this right — `5,247.070 USD millions (= $5.25B)` — so adopt that pattern here.
- **No cell preview.** The only way to see the cell is *Download workbook (.xlsx)*. The product promise is that a citation opens the source with the exact cell highlighted; the workbook tier does not do this. Render a small HTML table of the cited cells plus surrounding rows, server-side at build time.
- **Three cells, no arithmetic.** `O839 O840 O841` are summed with nothing saying so, and a reader cannot tell whether the three are variants, appropriations, or something else. Show each cell's own value and the operation joining them — schematically `O839 <a> + O840 <b> + O841 <c> = 5,565,655` — consistent with the "derived numbers show their inputs" rule the site applies elsewhere.
- **Cell refs are ambiguous in the current font.** Column `O` is visually identical to zero at 12px — I initially misread `O839` as `0839`. Use a font with a slashed or dotted zero for cell refs, PE numbers, and hashes.
- **Duplicate link.** "Official source" appears twice, same URL, ~250px apart.
- **Hash is truncated with no way to get the rest.** `4d965906…` and no copy-hash control. Add one.
- **No document identity.** The drawer says sheet and cells but never names the document or edition. PDF-tier drawers are worse: no document title, no page number, no row name — all recoverable only by squinting at the thumbnail.

## P1-10. Department-wide GAO findings render as program oversight

`/program/ATA000/` → Oversight → `⚠ GAO oversight: DOD – 5 high-risk areas`. That is a department-level designation shown on a program page with no qualifier, implying program-specific findings. On the F-35 specifically this is doubly unfortunate, since real program-level GAO work exists and this is not it. Label it "Department-level designation (not specific to this program)", visually de-emphasize relative to program-specific findings, and treat program-level GAO report ingestion as a roadmap item.

## P1-11. The 1,741-row program index has no text filter, though two sibling pages do

`/programs/` offers only an agency dropdown. `/years/` has "Filter by program, PE/BLI, or organization…" and `/companies/` has a name filter. Port the filter to `/programs/`, add sort on Org, and add a CSV export to match `/years/`.

# P2 — Performance, accessibility, polish

## P2-1. Page weight

| Page | HTML | DOM |
|---|---|---|
| `/years/` | **9.1 MB** | 1,765 rows / 22,681 cells |
| `/programs/` | **4.8 MB** | 1,741 rows |
| `/` | 1.2 MB | |

Every row of every table is in the initial document, with no pagination or virtualization. On a fast desktop connection this is survivable (DCL ~320ms warm). On a phone on 4G — which is where Hill staff read things — a 9 MB document is a bad experience, and `/years/` on mobile additionally requires scrolling past 33 column-toggle chips before reaching any data. Introduce server-side pagination or windowed rendering with the full dataset behind CSV and the Data Explorer, both of which already exist.

## P2-2. `/years/` defaults to a screenful of dashes

Default sort is alphabetical, so the first rows are `COUNTER-SMALL UNMANNED AERI…`, `Physical Security Systems`, `Heaters and ECU's` — a decade of "—". The flagship decade view opens looking empty. Default to descending FY26 total, or to data density.

## P2-3. Charts are not accessible and Sankey labels collide

Three of five SVGs on the program page have neither `<title>` nor `aria-label`; no table has a `<caption>`. On `/flow/`, node labels overlap and truncate — "Shipbuilding and Conversion…avy 47.4B", "Fleet ballistic missile ships 1?.?B". Add accessible names and short descriptions to every chart, ship a "view as table" toggle beside each (the data is already tabular), and add collision detection or leader lines to the Sankey. Positive note: `th scope` is set on every table header and a skip link is present — the fundamentals are there.

## P2-4. Company names render as raw registry strings

`LOCKHEED MARTIN CORPORATION` as an `<h1>`, across 200 pages. Title-case for display, keep the raw registry string in a "registered name" field where it belongs as provenance.

## P2-5. `og:description` starts mid-thought

Program OG descriptions are raw justification prose: *"The FY 2026 budget provides funding for 24 F-35A Aircraft, Engines and associated Non-Recurring and ancillary…"*. The OG **image** is excellent — clean, on-brand, "Every number cited". Give the description the same care: `F-35 (ATA000): $4.09B requested for FY2026, $5.57B obligated in FY2024. Every figure links to the J-book page it's printed on.` Note the image currently shows the FY26 request from the basis under dispute in P0-1 — fix that alongside.

## P2-6. Amber caveat banners read as errors, and are overused

Coverage notes, "medium confidence", non-additivity warnings, and GAO flags all render in the same amber warning treatment. On `/district/CO-05/` the coverage banner sits **above the `<h1>`**, so the page opens with a warning before the reader knows what page they are on. Introduce a distinct visual language for *honest scope disclosure* (calm, informational) versus *caution about a specific number*, and put the H1 first.

## P2-7. "0.0" in the years matrix is ambiguous

Cited cells render as `0.0` where the value is a true zero and, apparently, where it rounds to zero. Distinguish: `0` for a real zero, `<0.05` for a rounded-down nonzero, `—` for absent.

## P2-8. Rounded display values make derived arithmetic non-reproducible

`/program/ATA000/`: *"the PB2024 book requested $5.28B for FY2024; the PB2026 book reports $5.57B actually spent — $286.5M above the request."* From the displayed figures a reader computes $290M. The stated $286.5M is right — it uses unrounded inputs — but a reader checking the site's arithmetic against the site's own displayed numbers finds a discrepancy, which is precisely the audience this feature is for. Show unrounded inputs in derivation strips, or state the rounding explicitly.

# Systemic fix: make P0-1 impossible to reintroduce

The codebase already enforces "cited or absent" with automated gates. Extend that culture with a second invariant, which would have caught P0-1, P0-2, and P0-5 at build time:

> **One label, one basis.** Every rendered figure carries `(entity, fiscal_year, measure, basis, edition)`. Two figures on a page sharing `(entity, fiscal_year, measure)` but differing in `basis` MUST either render identical values or render inside a declared reconciliation component.

Three build-time checks:

1. **Intra-page consistency.** For every generated page, group figures by `(entity, fiscal_year, measure)`. Fail the build on any group with >1 distinct value not wrapped in a reconciliation component.
2. **Summary/detail agreement.** For every summary card, assert its value appears in the detail sections below, and that a card rendering "—" has no corresponding non-null detail fact. This alone catches P0-2.
3. **Footnote completeness.** Assert every citation tier's footnote contains unit, fiscal year, field name, document title, locator, hash, retrieval date, and fact permalink. Golden-file one footnote per tier.

Also worth adding to the existing 50-facts-per-build provenance spot-check: verify the **highlighted region** matches the expected row label, not merely that the document exists and the hash matches. P0-1's underlying mislabel would not have been caught by an existence check.

# Coverage: the honesty is right, the roadmap is missing

Disclosed on the site today:

| Feature | Coverage |
|---|---|
| Follow-the-dollar flows | 17 of 1,741 programs (10 PEs bridged, 6 high-confidence) — **98.7% of FY26 request unbridged** |
| Research dossiers | 50 of 1,741 |
| Company award linkage | 18 of 200 |
| District lens | 106 of 435 districts |
| California state data | FY2025 only |

Every one of these is disclosed clearly and in the right place. That is genuinely rare and should not change. What is missing is any forward-looking statement, so a visitor cannot distinguish "early, moving fast" from "abandoned at 1%."

Three recommendations. First, publish a **coverage page** with the current numbers, the specific blocker for each, and a dated target — the crosswalk gap is a methodology problem (account codes are too coarse to defend program-level links outside DARPA's clean structure), and saying so plainly converts a weakness into a credibility asset. Second, **reframe Flow's default view**: instead of leading with a bridge that carries 1.3% of dollars, lead with the two rivers side by side as the *finding* — "the Pentagon's budget system and its contract system cannot be mechanically reconciled, and here is exactly how far you can get" — which is a real, publishable insight rather than an apology. Third, consider a **medium-confidence exploration mode**, clearly walled off and non-citable, that lets users see candidate links the site will not assert. That serves the "contractor tracking competitors" audience without compromising the citation standard, and the methodology's three-tier structure already supports it.

# What is working — do not regress these

- **The methodology page.** Nine named limitations, per-feature coverage counts, three-tier confidence definitions, supersede-not-delete, explicit refusal to interpolate or fuzzy-match renames. Best-in-class. Link to it more prominently than the footer.
- **The PDF receipt.** Rendered page, highlighted cell, Enlarge, official source, hash, retrieval date. This is the product, and it works.
- **Flow's framing.** "Two rivers, deliberately kept apart… an honest gap, not an absence of contractors." Move this to the homepage.
- **Empty-state copy.** "No awards are linked to this program element at high confidence — the budget→award crosswalk only asserts links it can defend, and this line has none yet." Whoever writes these should write the rest of the site.
- **Edition-honest columns** on `/years/` — each column stamped with its PB edition, with actuals drawn from PB(N+2). Exactly right, and rare.
- **Data Explorer.** DuckDB-WASM, 14 datasets, in-browser SQL, no server sees the query. Serious credibility with technical users.
- **Anomaly feed** with published thresholds and per-item "why flagged?".
- **404 page** with three recovery paths, and a global "Data as of" stamp in the footer.
- **Full-text search** with highlighted snippets that finds GBSD from "Sentinel".
- **Mobile layout** on program pages — cards stack cleanly, the decade table stays readable, the citation drawer works.
- **OG images** — clean, per-program, on-brand.
